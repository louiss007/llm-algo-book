# 附录 E 主流开源模型架构参数对照表

本附录把第 3–7 章的架构分析落到具体模型配置上，分为稠密模型、MoE 模型、结构选择、参数与缓存账本四部分。表内数字取自各模型公开技术报告与正文已核对的配置；正文没有列出、也无法从公开报告确认的单元格用“—”表示，不做推测。参数量的“约”表示按公开报告四舍五入到三位有效数字。

{% hint style="info" %}
读这张表先看四个量：总参数、每 Token 激活参数、词表大小、上下文长度。总参数决定权重占多少显存，激活参数决定每 Token 的计算量，词表决定嵌入层与输出层的参数占比，上下文决定 KV Cache 的上限。只看“多少 B”会把 MoE 的显存成本和稠密模型的计算成本混在一起。
{% endhint %}

这张表要横着读：同一行是某个模型家族的组合，同一列是某个设计维度上的不同选择。几个容易被忽略的例外：

- **归一化不是只有 RMSNorm。** PaLM 540B 仍用 LayerNorm，说明 RMSNorm 是现代主流，不是大规模训练的必要条件；它省下的参数不到万分之几，收益主要在算子数量与数值行为。
- **门控前馈不只有 SwiGLU。** Gemma 用 GeGLU，把门控激活从 SiLU 换成 GELU；两者都属于 GLU 家族，差距依赖数据与规模。
- **注意力不是单调走向“更省”。** PaLM 用 1 个 KV 头的 MQA，Llama 3 与 Mistral 用 8 个头的 GQA，DeepSeek 用 MLA。MQA 缓存最小但表达力与训练稳定性风险最高；GQA-8 只多花一点缓存，就把风险降下来；MLA 用低秩压缩换更小的缓存，代价是实现复杂。
- **权重绑定没有统一答案。** Gemma 与 PaLM 绑定，Llama、Mistral、DeepSeek 不绑定。绑定省下 $$n_{vocab}d_{model}$$，但强制输入与输出共享几何；词表越大、模型越宽，这个取舍越需要单独算账。
- **块结构有串行与并行两种。** PaLM 用并行注意力—前馈块合并通信，Llama 与 Qwen 仍用串行块。并行块的收益依赖张量并行实现，不是单向的“更先进”。

## E.4 参数量、权重与 KV Cache 的快速估算

稠密解码器的参数量可以按层拆开。使用 MHA 时，每层注意力有 $$4d_{model}^2$$ 个参数；使用 GQA 时，查询与输出投影仍是 $$2d_{model}^2$$，键与值投影变成 $$2d_{model}n_{kv}d_h$$。SwiGLU 前馈每层有 $$3d_{model}d_{ff}$$ 个参数，两个 RMSNorm 各贡献 $$d_{model}$$。把 $$L$$ 层相加，再加输入嵌入与输出投影（不绑定时各一份），就得到总参数。

MoE 把每层的前馈替换成 $$E$$ 个专家，总参数按全部专家计，每 Token 激活参数只按 Top-K 选中的专家计；共享专家始终激活，也要计入激活参数。路由器的参数很少，但在小模型上不能忽略。

推理侧的两个常用估算：

- **KV Cache**：每 Token 的字节数为 $$2Ln_{kv}d_hb$$，其中 $$b$$ 是每个标量的字节数，FP16/BF16 为 2，FP8 为 1。再乘以上下文长度与批量，就是缓存总量。
- **权重显存**：FP16/BF16 为 $$2N$$ 字节，FP8 为 $$N$$ 字节，4-bit 约为 $$0.5N$$ 字节再加缩放因子与对齐开销。MoE 的 $$N$$ 要用总参数，不是激活参数。

Llama 2 7B 的 6.74B 可以进一步拆开：注意力 2.147B、前馈 4.329B、归一化 0.266M、嵌入与输出 0.262B。前馈占非嵌入参数的 66.8%，这是“参数大头在前馈，不在注意力”的直接证据。把同样的账本套到 Llama 3 8B，多出的 1.292B 分别来自更宽的前馈、更大的词表与 GQA 省回的一部分，三项可以逐项对上。

把第 6 章的账本代入几个代表模型，得到下表。KV Cache 统一按 8K 上下文、FP16、批量 1 计算：

| 模型 | 参数量 | FP16 权重 | 8K KV Cache | 备注 |
| --- | --- | --- | --- | --- |
| Llama 2 7B | 6.74B | 12.6 GiB | 4 GiB | MHA，32 个 KV 头 |
| Llama 3 8B | 8.03B | 15.0 GiB | 1 GiB | GQA-8，缓存为 Llama 2 7B 的 1/4 |
| Mistral 7B | 7.24B | 13.5 GiB | 1 GiB | GQA-8 + SWA，常驻缓存可截到 4096 Token |
| Mixtral 8x7B | 46.7B | 87 GiB | 1 GiB | 激活 12.9B，权重按 46.7B 存 |
| DeepSeek-V2 | 236B | 440 GiB | 540 MiB | MLA，60 层 |
| DeepSeek-V3 | 671B | 1.22 TiB | 约 549 MiB | MLA，61 层；需多机部署 |

这张表最值得记的不是具体数字，而是三组比例：

- Llama 2 7B 与 Llama 3 8B 的层数、宽度、查询头数都相同，只把 KV 头从 32 降到 8，8K 缓存就从 4 GiB 降到 1 GiB。头共享对缓存是线性缩放。
- Mixtral 的权重是 Llama 3 8B 的约 5.8 倍，8K 缓存却相同，因为两者的层数、KV 头数与单头维度相同。MoE 放大的是权重，不是每 Token 的缓存。
- DeepSeek-V3 的参数量是 Llama 3 8B 的约 84 倍，8K 缓存却只有约 0.54 倍，因为 MLA 把每 Token 每层压到 576 个标量。缓存维度与查询头数解耦，是 MLA 与 GQA 的关键差别。

## E.5 使用这张表的注意事项

{% hint style="warning" %}
表中的配置对应各技术报告发布时的版本。模型后续可能改动词表、层数、上下文或注意力实现；商用前必须回到原始模型卡与许可条款。开放权重也不等于 OSI 认证的开源许可，Llama、Gemma、DeepSeek、Kimi 的许可范围各不相同。
{% endhint %}

- **总参数不等于计算量。** 稠密模型每 Token 的计算约与总参数成正比；MoE 只与激活参数成正比。把 Mixtral 的 46.7B 当成每 Token 46.7B 的计算量，会把算力预算高估约 3.6 倍。
- **参数量不等于显存。** 权重显存按总参数算，训练还要加梯度、优化器状态与激活。混合精度训练每个参数约 18 字节，是推理权重的 9 倍；MoE 的训练显存门槛比推理更高。
- **词表会吃掉小模型的容量。** Llama 3 8B 的嵌入与输出层约 1.05B 参数，占总参数约 13%。词表从 32K 扩到 128K 提高压缩率，但在小模型上会挤占前馈与注意力的预算。
- **上下文不是免费的。** KV Cache 随层数、KV 头数、单头维度、上下文与批量线性增长。GQA、MLA、SWA 分别从“每 Token 存几份”“每份多宽”“保留多少 Token”三个方向削减缓存，彼此正交。
- **结构选择有例外。** 看到“现代模型都用 RMSNorm + SwiGLU + RoPE + GQA”时，要同时记住 PaLM 的 LayerNorm、Gemma 的 GeGLU、DeepSeek 的 MLA、Mistral 的 SWA。默认值是起点，不是定律。

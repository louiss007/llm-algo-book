# 大语言模型算法：从 Transformer 到推理模型

> 大模型的能力来自“架构 × 数据 × 算力 × 训练目标”的共同作用。理解算法，就是理解每一个设计在这四者之间做了什么取舍。

这是一本讲“为什么”的书。它不满足于罗列模型组件，而是把每个设计放回它诞生时的约束里：**为了解决什么问题、付出了什么代价、有没有更好的替代方案**。

## 这本书回答四个问题

1. **架构**：现代大语言模型由哪些组件构成？每个组件为什么这样设计？
2. **能力的来源**：预训练、后训练、强化学习各自起什么作用？
3. **效率**：怎样高效地训练和推理一个大模型？
4. **前沿**：当前有哪些方向，还有哪些问题没有解决？

**目标**：能判断一个模型/框架的能力边界，知道什么时候该换模型、什么时候该改提示、什么时候该上检索或微调。

**建议顺序**：第 1 → 2 → 3 → 5 → 6 → 13 → 14 → 18 → 20 → 21 → 23 → 24 → 26 → 27 章，约 **15–18 小时**。

**可以跳过**：第 4、7、8、9、10、11、12、15、16、17、19、22、25、28、29 章。跳过的章节遇到时再回查即可。

**重点**：分词为什么会影响计费与效果（第 2 章）、KV Cache 为什么决定了并发成本（第 6、21 章）、长上下文与 RAG 的取舍（第 13 章）、推理模型什么时候值得用（第 18、24 章）、评测结论为什么经常不可信（第 27 章）。

### 路线二：算法工程师

**目标**：能独立完成从数据、预训练、后训练到推理部署的全流程，并能定位训练不收敛、显存溢出、推理变慢这类问题。

**建议顺序**：第 1–29 章顺序阅读，约 **40–50 小时**。

**重点章**：第 3（Transformer）、6（注意力变体）、7（MoE）、12（分布式训练）、16（RLHF）、18（RLVR 与推理模型）、21（推理加速）、23（量化）章需要精读并跑通代码。第 8、19、22、25 章可以略读，用到时再深入。

### 路线三：研究者

**目标**：快速建立领域地图，找到值得投入的开放问题。

**建议顺序**：第 3 → 4 → 6 → 7 → 8 → 9 → 12 → 13 → 16 → 17 → 18 → 24 → 28 → 29 章，约 **25–30 小时**；配合[附录 D 必读论文清单](appendix/d-papers.md)精读原始论文。

## 贯穿全书的 TinyLM

全书用一个从零实现的小模型 **TinyLM** 串联。它只依赖 PyTorch，目标是在**单张 24GB 消费级显卡**上跑通，同时提供 **CPU 可跑的缩小版**。

TinyLM 不是玩具示例：它的配置项覆盖了本书讨论的主要架构选择（归一化类型、激活函数、注意力变体、位置编码、MoE、线性注意力与 SSM 块），你可以通过改配置复现“如果换成另一种设计会怎样”的对照实验。

代码的目录结构、接口契约和逐章演进路线见[附录 F](appendix/f-tinylm.md)。

- 引用论文时给出作者、年份和标题；不确定的细节不写。
